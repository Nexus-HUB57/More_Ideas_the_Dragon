# Integração segura: Nexus App Dev no Opal e projeto móvel MMN

## Escopo

Este documento registra a integração realizada na branch `agent/safe-import-mobile-opal-20260822` a partir do projeto local `mmn-mobile-app` e da inspeção da aplicação publicada **Nexus App Dev** no Opal. O objetivo foi preservar o conteúdo existente do repositório e criar uma área de importação isolada, sem sobrepor arquivos ou históricos.

## Origem Opal

A referência fornecida foi aberta em [https://opal.google/app/1BmyCCIEcF78_rtuKa9I3wyC2OdJk5d9o](https://opal.google/app/1BmyCCIEcF78_rtuKa9I3wyC2OdJk5d9o). A interface mostrou um workflow visual publicado com os blocos `Fetch Foundation Blockchain Data`, `Moltbook URL Context`, `Fetch Moltbook Skill Docs`, `Synthesize Claw Sentinel Specs`, `Simulate Claw Sales Flow`, `Synthesize Claw Sentinel Narrative`, `Generate Claw Sentinel Avatar`, `Construct Nexus Claw Dashboard`, `Blockchain Data Url`, `User Input` e `User Input 1`.

A navegação foi passiva. O workflow não foi iniciado, remixado, compartilhado, editado ou publicado. A página não ofereceu, nos elementos acessíveis, um exportador direto de código-fonte. Por isso, este commit **não afirma que o código interno do Opal foi exportado**. Ele preserva somente o inventário observável e a rastreabilidade da origem; uma exportação real deverá ser adicionada quando o usuário fornecer o arquivo oficial ou disponibilizar uma opção de exportação.

## Área importada

O projeto móvel foi copiado para `imports/mmn-mobile-app-m1-20260822/`, um caminho novo criado nesta operação. Foram importados 91 arquivos, sem `node_modules`, `.expo`, logs de desenvolvimento ou diretório Git interno. Nenhum caminho existente do repositório foi utilizado como destino da cópia.

O projeto contém Expo SDK 54, React Native, TypeScript, Expo Router, NativeWind, cliente tRPC, telas iniciais de autenticação, navegação por abas, design system, ícones e configurações de branding. O import é um snapshot de trabalho; ele não altera automaticamente os bundles existentes nem substitui implementações de outros desenvolvedores.

## Protocolo de preservação

A branch principal foi encontrada limpa e alinhada ao commit `f1da34e551aa5cec65d49782adf3560d2f2285e9`. Antes da importação, foi criada uma branch de trabalho própria e um Git bundle de recuperação fora do repositório. O bundle possui SHA-256 `d80c7af2df0eb9fc4092b4193175ae5c452ab910ba4f98294d91e0c8a72e2686` e está em `/home/ubuntu/safe-recovery-backups/More_Ideas_the_Dragon_before_mobile_opal_20260822.bundle` durante a sessão.

Não foram usados `git reset --hard`, `git clean`, rebase destrutivo ou operações de remoção sobre o conteúdo pré-existente. A única correção destrutiva executada durante a operação removeu artefatos não rastreados criados acidentalmente por um comando de cópia que apontou para a raiz já existente de `imports`; o estado Git voltou a ficar limpo antes da importação correta em namespace novo.

## Segurança

A inspeção identificou nomes de arquivos potencialmente sensíveis já presentes no repositório, incluindo `credentials.json`, arquivos de ambiente e material nomeado como chave privada. Esses conteúdos não foram abertos, copiados para o snapshot móvel nem incluídos deliberadamente em novos artefatos. A existência prévia desses caminhos deve ser tratada como pendência de auditoria independente e não como autorização para expô-los, alterá-los ou removê-los nesta tarefa.

## Limitações e pendências

A exigência de “295/299 arquivos” já possui um manifesto existente em `PHD_EndToEnd_Validation/MANIFEST_PHD_299_FINAL.txt`, que lista 299 entradas históricas. A validação encontrou uma entrada ausente correspondente a arquivo de ambiente e algumas entradas não rastreadas, portanto a contagem do manifesto não deve ser interpretada automaticamente como 299 arquivos seguros e rastreados. A próxima etapa produzirá um manifesto novo, relativo e baseado apenas no snapshot importado, além de seus hashes.

A integração do código-fonte interno do Opal permanece bloqueada pela ausência de exportação acessível. Nenhum código foi inventado a partir dos nomes dos blocos. Caso a origem possa ser exportada, o arquivo deverá entrar em novo namespace, passar por revisão de segredos e ser comparado antes de qualquer integração funcional.
